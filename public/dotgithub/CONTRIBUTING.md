# Contributing to Red Flag Club

Thank you. Everything here exists to stop people losing their savings to pump-and-dump groups, so every change goes through the same reviewed path:

**issue → spec → plan → tasks → code → review**, with a maintainer approving each step on the [project board](https://github.com/orgs/red-flag-club/projects).

1. **Open an issue** with the right form. Each one asks *what*, *why* and *how*.
2. **Wait for triage.** A maintainer moves it to *Specify* (or explains why not).
3. **Write or help write the spec** (`specs/NNN-name/spec.md`, GitHub Spec Kit). It is reviewed, then *Plan*, then *Tasks*.
4. **Code** once the issue is in *Implement*: a PR that says `Closes #N` and ticks the hard-rules checklist. The `spec-gate` check enforces both.
5. **Review**: a maintainer reads the diff against the spec and merges.

The full guide, with the hard rules, the local set-up and what we never merge, is in the code repo: [CONTRIBUTING.md](https://github.com/red-flag-club/red-flag-club/blob/main/CONTRIBUTING.md) and [docs/workflow.md](https://github.com/red-flag-club/red-flag-club/blob/main/docs/workflow.md).

**Never post personal data** in issues, PRs or discussions: not yours, not anyone else's. No chat screenshots, phone numbers, account numbers or group links. Stories go only through the site's encrypted form.
